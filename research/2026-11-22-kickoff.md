# 2026-11-22 — Kickoff

## Context
- Baseline: Behrang Lab `artarget.html` — MindAR 1.2.5 (hand-crafted features), user captures any surface with the live camera, compiles in-browser (~5 s in headless Chrome test, 812–1489 feature points on textured surfaces), on-camera gizmo (move on surface plane, pinch scale/twist rotate, lock).
- Tested Prototype: works with a fake camera in headless Chrome; first real-phone test by Behrang: "works".

## Why phones without ARCore fail
- ARCore is software-locked to certified models; each model has a runtime calibration profile (intrinsics, camera–IMU time offset). Spoofing the model ID runs it but with another phone's calibration → scale error, drift, jitter.
- iPhones all work because Apple factory-calibrates a small set of models.
- Browsers do not expose synchronized camera+IMU timestamps or intrinsics → no real VIO on the web without ARCore.

## Decisions
- Phase 1 detector: **XFeat** (Apache-2.0) + **LighterGlue** (Apache-2.0). SuperPoint avoided (non-commercial weights).
- Runtime: ONNX Runtime Web, WebGPU EP (still marked experimental) with WASM fallback.
- Markerless (Phase 3) is research-grade: online calibration (OpenVINS-style, GPL-3) — license decision later.

## Open questions
- XFeat inference time on a budget Android in the browser (WebGPU availability on Android Chrome for that GPU?).
- How much does gyro fusion help when DeviceMotion timestamps are not synchronized with frames? Phase 0 captures measure the offset.
